crypto-go fix/bugs — bug explainer

Branch fix/bugs (12 commits on top of main) fixes denial-of-service panics and silent data-corruption bugs found by a gstyle --skill scan. Tests were green before and after — none of these paths were exercised.

Verify locally: git log --oneline main..fix/bugs · go test $(go list ./... | grep -v stream/internal)

1. Nil signature panics in every Verify

DoS · paniceddsa · mldsa · rsa · xdsa
Before
func (k *PublicKey) Verify(msg []byte, sig *Signature) error {
    mPrime := cmldsaMessagePrime(msg)
    mlSig, edSig := sig.Split() // nil → panic
    ...
After
func (k *PublicKey) Verify(msg []byte, sig *Signature) error {
    if sig == nil {
        return ErrInvalidSignature
    }
    ...

Any lookup-miss or failed decode forwarded as nil crashed the process instead of failing authentication. A remote kid + missing key = crash. Now it returns a normal verification error.

Commits: eddsa 4be2a07 · mldsa 6a8147b · rsa f76444e (Verify + VerifyHash) · xdsa 3bcb563. Reproduced before: nil pointer dereference; after: signature verification failed.

4. Swallowed marshal errors in COSE verify

hygiene · error maskingcose/cose.go:488,584
Before
toBeSigned, _ := cbor.Marshal(&sig)
After
toBeSigned, err := cbor.Marshal(&sig)
if err != nil {
    return err // (or nil, err)
}

Not exploitable today (fixed context string, non-nil buffers), but a future struct change could make marshal fallible — then verify would run over nil bytes and misreport ErrInvalidSignature instead of the real cause.
